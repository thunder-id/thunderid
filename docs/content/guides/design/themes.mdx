# Themes

A theme defines the visual styling for your application's authentication screens. Create custom themes to match your brand identity or use the default theme that ships with <ProductName />.

## Theme Properties

Each theme includes the following configurable properties. For detailed property references, see [Design Catalog](../design-catalog#theme-properties).

| Property | Description |
|----------|-------------|
| **Color Schemes** | Light and dark color palettes covering primary, secondary, semantic, background, and text colors. See [Color Schemes](../design-catalog#color-schemes). |
| **Shape** | Corner radius for cards, buttons, and inputs. See [Shape](../design-catalog#shape). |
| **Blur Effects** | Frosted glass (acrylic) backgrounds at multiple intensity levels. See [Blur Effects](../design-catalog#blur-effects). |
| **Gradients** | CSS gradients for primary and secondary surfaces. See [Gradients](../design-catalog#gradients). |
| **Typography** | Font family selection with support for browser-safe and Google Fonts. See [Typography](../design-catalog#typography). |
| **Text direction** | Left-to-right or right-to-left text rendering. See [Text Direction](../design-catalog#text-direction). |
| **Component Overrides** | CSS-in-JS styling for individual UI components such as buttons, text fields, and dialog boxes. See [Component Overrides](../design-catalog#component-overrides). |

<ProductName /> ships with a default theme. For details, see [Default Theme](../design-catalog#default-theme).

## Create a Theme

<Stepper stepNode="h3" as="h3">

### Open the Theme Builder

1. Sign in to the <ProductName /> Console.
2. Navigate to **Design** from the sidebar.
3. In the **Themes** section, click **Add theme**.

### Enter a Theme Name

Enter a name for your theme. Pick one of the suggested names or type a custom name.

Click **Continue** to proceed.

### Select a Primary Color

Select one of the preset colors (Indigo, Blue, Cyan, Teal, Green, Orange, Red, Pink, Purple, or Slate) or use the color picker to set a custom primary color.

The live preview on the right shows how the selected color appears on the sign-in screen.

Click **Create theme** to generate the theme and open the theme builder.

### Customize the Theme

The theme builder opens with a live preview in the center. Use the left panel to configure:

- **Colors**: Adjust light and dark color palettes.
- **Shape**: Set the border radius for UI elements.
- **Typography**: Choose a font family and configure font weights.
- **Default color scheme**: Select **Light**, **Dark**, or **System**.
- **Default text direction**: Select **Left-to-Right** or **Right-to-Left**.

Click **Save** to apply your changes.

### Assign the Theme to an Application

Open your application in the <ProductName /> Console, navigate to **Customization** settings, and select your theme.

</Stepper>


## Update a Theme

1. Navigate to **Design** in the <ProductName /> Console and click the theme you want to edit. The theme builder opens with a live preview.
2. Use the left panel to edit **Colors**, **Shape**, **Typography**, **Default color scheme**, and **Default text direction**.
3. Click **Save** to apply your changes. To discard unsaved changes, click **Revert**.

Changes take effect immediately for new authentication sessions.

## Scope Themes to a Project

On the control plane, every theme you manage through the REST API, the MCP server, or an import belongs to a project. Pass the project ID when you work with these themes.

- **Create**: set `projectId` in the body of `POST /design/themes`. A request without `projectId` fails with `THM-1019`.
- **Update**: a `PUT /design/themes/{id}` without `projectId`, or with the current one, keeps the theme in its project without checking the project again. A different `projectId` moves the theme to that project.
- **List**: `GET /design/themes?projectId=<project-id>` returns the themes in the project, and its pagination links keep the `projectId` filter. An empty `projectId=` returns an empty list. A project that does not exist can still return declarative themes that name it.
- **MCP tools**: `list_themes` takes `projectId` and lists the themes in that project. Unlike the REST filter, an empty or omitted `projectId` lists every theme. `list_themes` and `get_theme_by_id` return each theme's `projectId`, and leave the field out for a theme without a project.
- **Resource files**: a `theme` document in an import or a bootstrap file that creates a theme goes through the same project checks as `POST /design/themes`. One that updates an existing theme follows the update rules above, so without `projectId` the theme keeps its current project. A dry run does not check the project, so it can report success for a document that fails when you apply it. A declarative resource file can set `projectId`, but its loader does not check it. A declarative theme without `projectId` appears in no project's list in the Console, and one that names a project that does not exist still appears in a list filtered by that project ID. Exports write `projectId` when the theme has one.
- **Delete the project**: a project that still has a theme cannot be deleted. `DELETE /projects/{projectId}` fails with `PRJ-1013` and `409` until you delete the project's themes or move them to another project. Declarative themes are read-only, so remove them from your resource files or change their `projectId`, then restart the server before you delete the project again.
- **Console**: select a project to see its themes under **Design**. A theme you create there belongs to the project, and an application's theme picker offers the themes of the application's project. The default themes that <ProductName /> creates at startup belong to the default project.

A project that does not exist fails a create, or an update that moves the theme to it, with `THM-1018`. `THM-1018` and `THM-1019` both return `400`.

A data plane, such as the all-in-one server, has no projects. It keeps a `projectId` it receives without checking it and does not require one, so configuration imported from a control plane keeps its project. On every server, a `projectId` longer than 36 characters fails with `THM-1018`.

## Delete a Theme

1. Navigate to **Design** in the <ProductName /> Console.
2. Click the theme you want to delete to open the theme builder.
3. Click the **Delete** button in the top-right corner and confirm the deletion.

:::warning
You cannot delete a theme that is currently assigned to an application. Remove the theme from all applications before deleting it.
:::

# Server Actions

The <ProductName /> Next.js SDK provides server actions for authentication, session management, and user operations. These run only on the server and never expose tokens to the client.

Import all server actions from `@thunderid/nextjs/server`.

## Authentication

### `signInAction()`

Start the sign-in flow. By default, redirects the user to the <ProductName /> sign-in page. Optionally accepts parameters for embedded sign-in flows.

```ts
import { signInAction } from '@thunderid/nextjs/server'

// Redirect-based sign-in (default)
await signInAction()

// With embedded flow payload (advanced)
await signInAction(payload, requestConfig)
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `payload` | `EmbeddedSignInFlowHandleRequestPayload` | Optional payload for embedded sign-in flows |
| `requestConfig` | `EmbeddedFlowExecuteRequestConfig` | Optional request configuration for embedded flows |

### `signOutAction()`

Sign out the current user and clear the session cookie.

```ts
import { signOutAction } from '@thunderid/nextjs/server'

await signOutAction()
```

### `signUpAction()`

Start the sign-up flow.

```ts
import { signUpAction } from '@thunderid/nextjs/server'

await signUpAction()
```

### `refreshToken()`

Manually refresh the access token.

```ts
import { refreshToken } from '@thunderid/nextjs/server'

const result = await refreshToken()
// result.expiresAt — token expiry timestamp
```

**Returns:** `Promise<{ expiresAt: number }>`

## Session

### `isSignedIn()`

Check whether the current user is authenticated.

```ts
import { isSignedIn } from '@thunderid/nextjs/server'

const authenticated = await isSignedIn()
```

**Returns:** `Promise<boolean>`

### `getSessionId()`

Retrieve the current session ID.

```ts
import { getSessionId } from '@thunderid/nextjs/server'

const sessionId = await getSessionId()
```

**Returns:** `Promise<string | undefined>`

### `getSessionPayload()`

Retrieve the full session token payload including user ID, scopes, and organization.

```ts
import { getSessionPayload } from '@thunderid/nextjs/server'

const session = await getSessionPayload()
if (session) {
  console.log(session.sub, session.scopes)
}
```

**Returns:** `Promise<SessionTokenPayload | undefined>`

### `getAccessToken()`

Retrieve the current access token for making authenticated API calls from the server.

```ts
import { getAccessToken } from '@thunderid/nextjs/server'

const token = await getAccessToken()
```

**Returns:** `Promise<string | undefined>`

### `clearSession()`

Clear the session cookie without triggering a sign-out flow.

```ts
import { clearSession } from '@thunderid/nextjs/server'

await clearSession()
```

## User Management

### `getUserAction()`

Retrieve the authenticated user's profile.

```ts
import { getUserAction, getSessionId } from '@thunderid/nextjs/server'

const sessionId = await getSessionId()
const result = await getUserAction(sessionId)

if (result.success) {
  console.log(result.data.user)
}
```

**Returns:** `Promise<{ data: { user: User | null }; error: string | null; success: boolean }>`

### `getUserProfileAction()`

Retrieve the extended user profile.

```ts
import { getUserProfileAction, getSessionId } from '@thunderid/nextjs/server'

const sessionId = await getSessionId()
const result = await getUserProfileAction(sessionId)

if (result.success) {
  console.log(result.data.userProfile)
}
```

### `updateUserProfileAction()`

Update the current user's profile.

```ts
import { updateUserProfileAction } from '@thunderid/nextjs/server'

const result = await updateUserProfileAction({
  name: { givenName: 'Jane', familyName: 'Doe' },
})
```

## Organization Units

Switching organization units runs through a server action inside the SDK, so call it from a client component with `useThunderID()` from `@thunderid/nextjs`. The hook returns these organization unit members:

| Member | Type | Description |
|--------|------|-------------|
| `currentOrganizationUnit` | `CurrentOrganizationUnit \| null` | The organization unit the session was issued for, or `null`. The SDK reads it on the server from the `ouId`, `ouHandle`, and `ouName` claims of the session's access token, for display only. An access token carries `ouId` only when the application's token configuration includes it. |
| `getCurrentOrganizationUnit` | `() => Promise<CurrentOrganizationUnit \| null>` | Reads the current organization unit from the session's access token again. |
| `switchOrganizationUnit` | `(organizationUnitId: string, options?: SwitchOrganizationUnitOptions) => Promise<User \| undefined>` | Signs in again bounded to another organization unit. |

For how organizations map to organization units and what the new tokens carry, see [Switch Organizations](../../../../use-cases/b2b/journeys/switch-organizations). To let the user pick a unit, render [`<OrganizationUnitSwitcher />`](../components/organization-unit-switcher).

### `switchOrganizationUnit()`

Signs the user in again bounded to the organization unit `organizationUnitId`. <ProductName /> reuses the single sign-on (SSO) session when the user can sign in to that unit, so the user normally enters no credentials.

```tsx title="app/components/OpenOrganization.tsx" showLineNumbers
'use client'
import { useState } from 'react'
import { useThunderID } from '@thunderid/nextjs'

function OpenOrganization({ organizationUnitId }: { organizationUnitId: string }) {
  const { currentOrganizationUnit, switchOrganizationUnit } = useThunderID()
  const [error, setError] = useState<string | null>(null)

  const open = () => {
    setError(null)
    switchOrganizationUnit?.(organizationUnitId).catch(() => setError('The organization could not be opened.'))
  }

  return (
    <>
      <p>Working in {currentOrganizationUnit?.name}</p>
      <button onClick={open}>Open organization</button>
      {error && <p role="alert">{error}</p>}
    </>
  )
}

export default OpenOrganization
```

The path the switch takes depends on the sign-in mode:

- **Redirect mode**, the default:
  1. When the session holds a device secret, which a sign-in that requested the `device_sso` scope returns, the server action exchanges it at the unit's token endpoint, `{baseUrl}/ou/{ouId}/oauth2/token`. The application needs the `urn:ietf:params:oauth:grant-type:token-exchange` grant. The unit's tokens replace the session and its cookie. The SDK then reads the user and the current organization unit again, refreshes the route, and resolves with the user, with no redirect. The device secret stays in the server's session store, which is per process, so after a restart the session holds none.
  2. Without a device secret, or when <ProductName /> needs the user or cannot use the secret, the server action builds the unit's authorization URL, `{baseUrl}/ou/{ouId}/oauth2/authorize`, and marks the session so the OAuth callback completes the switch. The browser goes to that URL, and the callback redeems the code at the unit's token endpoint and replaces the session. The promise resolves with `undefined`. With `{ redirect: false }`, this step fails with `InteractionRequired` instead.
- **Embedded mode** (`mode: 'embedded'`): the server action starts an `AUTHENTICATION` flow with `ouId`. When the flow completes at once, its assertion replaces the session cookie. The SDK then reads the user and the current organization unit again, refreshes the route, and resolves with the user. A flow that needs input fails with `InteractionRequired`.

Only `options.redirect` applies. A failed switch keeps the previous session and rejects with an error whose `code` is one of the `OrganizationUnitSwitchErrorCodes` values. `@thunderid/nextjs` does not export that constant, so compare `code` with the values:

| Code | Value | Cause |
|------|-------|-------|
| `UnauthorizedClient` | `switchOrganizationUnit-UnauthorizedClient-001` | The unit does not exist, or the application cannot be used from it. |
| `InteractionRequired` | `switchOrganizationUnit-InteractionRequired-001` | The user has to sign in again, and the switch could not interact with the user. |
| `InvalidOrganizationUnit` | `switchOrganizationUnit-ValidationError-001` | No organization unit ID was given. |
| `Failed` | `switchOrganizationUnit-ResponseError-001` | The switch failed for another reason, including a request with no session. |

### `getAccessibleOrganizationUnits()`

List the organization units the signed-in user can access, from `/users/me/ous`, on the server. The request uses the access token of the session in the request's cookie, and the token stays on the server.

```ts
import { thunderid } from '@thunderid/nextjs/server'

const client = await thunderid()
const { current, organizationUnits, totalResults } = await client.getAccessibleOrganizationUnits({ scope: 'siblings' })
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `scope` | `'siblings'` | Optional. Lists only the accessible units that share the parent of the current unit. Omit it to list every accessible unit. |
| `limit` | `number` | Optional. The maximum number of units to return. |
| `offset` | `number` | Optional. The zero-based offset of the first unit to return. |

**Returns:** `Promise<AccessibleOrganizationUnitList>`, one page with `current`, `organizationUnits`, `totalResults`, `startIndex`, and `count`. On failure it throws a `ThunderIDAPIError` with the status and code of the failure.

## `thunderid()` Client Access

For advanced use cases, access the server-side client directly:

```ts
import { thunderid } from '@thunderid/nextjs/server'

const client = await thunderid()

const token = await client.getAccessToken(sessionId)
const result = await client.exchangeToken(config, sessionId)
```

| Method | Description |
|--------|-------------|
| `getAccessToken(sessionId)` | Retrieve the access token for a session |
| `getSessionId()` | Retrieve the current session ID |
| `exchangeToken(config, sessionId)` | Perform a custom token exchange |
| `getAccessibleOrganizationUnits(options)` | List the organization units the signed-in user can access. See [`getAccessibleOrganizationUnits()`](#getaccessibleorganizationunits) |
| `reInitialize(config)` | Update SDK configuration at runtime |

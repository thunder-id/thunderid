# Integrate {{productName}} Authentication in Next.js Application (Custom UI Mode)

## Context
I have a Next.js application (App Router) and I want to integrate {{productName}}'s authentication system using the {{productName}} Next.js SDK with a custom sign-in UI instead of {{productName}}-hosted pages.

## Requirements
- Use @thunderid/nextjs SDK for authentication
- Render sign-in on a custom route (not a redirect to {{productName}}-hosted pages)
- Use the App Router (not Pages Router)
- Implement sign-in and sign-out with the SDK's own components
- Add middleware for route protection and automatic token refresh
- Display signed-in user's profile information

## Configuration
- **Application ID**: {{applicationId}}
- **Base URL**: https://localhost:8090 (or your {{productName}} instance URL)
- **Flow Secret**: `<your-flow-secret>`
- **Sign In Route**: /signin
- **Sign Up Route**: /signup
- **SDK**: @thunderid/nextjs

## IMPORTANT Configuration Rules
- Use environment variables for configuration (NOT props on the provider)
- Required env vars: NEXT_PUBLIC_THUNDERID_BASE_URL, NEXT_PUBLIC_THUNDERID_APPLICATION_ID, THUNDERID_FLOW_SECRET, NEXT_PUBLIC_THUNDERID_SIGN_IN_URL, NEXT_PUBLIC_THUNDERID_SIGN_UP_URL, THUNDERID_SECRET
- NODE_TLS_REJECT_UNAUTHORIZED=0 is only needed against a local ThunderID instance using a self-signed certificate; scope it to local development, never production, and disable ALL TLS verification only for that reason
- Never ask the developer to type or paste the Flow Secret into this conversation. If it is not supplied above, add a `THUNDERID_FLOW_SECRET` placeholder to `.env` and tell the developer to fill it in locally before running the app
- THUNDERID_FLOW_SECRET is a separate credential from an OAuth2 client secret; it authenticates this app when the native (embedded) flow starts and is sent in the `Flow-Secret` request header, never in the client secret's place
- Import ThunderIDProvider from '@thunderid/nextjs/server' (NOT from '@thunderid/nextjs')
- Import middleware utilities from '@thunderid/nextjs/server'
- Import UI components (`SignedIn`, `SignedOut`, `SignIn`, `SignUp`, `SignInButton`, `SignOutButton`, `UserDropdown`) from '@thunderid/nextjs'
- The `<SignIn>` and `<SignUp>` components drive the Flow Execution API directly (not an OAuth redirect) — render each directly on its own custom route (`app/signin/page.tsx`, `app/signup/page.tsx`), with no `SignedIn`/`SignedOut` wrapper needed
- `app/signin/page.tsx` must be a Client Component (`"use client"` at the top); import `useRouter` from `next/navigation`, initialize `const router = useRouter()`, then pass `onSuccess={() => router.push('/')}` to `<SignIn>`
- `<SignUp>` accepts an `afterSignUpUrl` prop
- `<SignInButton>` navigates to the local `NEXT_PUBLIC_THUNDERID_SIGN_IN_URL` route rather than redirecting to a hosted page
- NEVER redirect to a {{productName}}-hosted URL for sign-in or sign-up in this mode

## Implementation Steps
1. Create a Next.js app: npx create-next-app@latest my-nextjs-app
2. Navigate into the project: cd my-nextjs-app
3. Install @thunderid/nextjs: npm install @thunderid/nextjs
4. If the flow secret was not provided, add a `THUNDERID_FLOW_SECRET` placeholder to `.env` and tell the developer to fill it in before running the app
5. Create .env with NEXT_PUBLIC_THUNDERID_BASE_URL, NEXT_PUBLIC_THUNDERID_APPLICATION_ID, THUNDERID_FLOW_SECRET, NEXT_PUBLIC_THUNDERID_SIGN_IN_URL, NEXT_PUBLIC_THUNDERID_SIGN_UP_URL, THUNDERID_SECRET (add NODE_TLS_REJECT_UNAUTHORIZED=0 only for a local self-signed instance, never production)
6. Wrap root layout with <ThunderIDProvider> from '@thunderid/nextjs/server'
7. Create app/signin/page.tsx as a Client Component (`"use client"`), importing and initializing `useRouter` from `next/navigation`, and rendering `<SignIn onSuccess={() => router.push('/')} />` directly, with no `SignedIn`/`SignedOut` wrapper
8. Create app/signup/page.tsx rendering `<SignUp afterSignUpUrl="/" />` directly, with no `SignedIn`/`SignedOut` wrapper
9. Create proxy.ts with thunderIDProxy and createRouteMatcher from '@thunderid/nextjs/server' for route protection
10. Add SignedIn, UserDropdown, SignedOut, SignInButton, and SignOutButton components to other pages
11. Run: npm run dev

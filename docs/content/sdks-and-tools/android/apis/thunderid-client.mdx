# `ThunderIDClient`

`ThunderIDClient` is the core authentication client in the `dev.thunderid:android` library. It manages the full authentication lifecycle: initialization, sign-in (both app-native and redirect-based), session, token management, and user profile operations.

When you use the `dev.thunderid:compose` library, a `ThunderIDClient` instance is created and managed automatically. You can access it via `LocalThunderID.current.client` from any composable.

## Usage

```kotlin
import dev.thunderid.android.ThunderIDClient
import dev.thunderid.android.ThunderIDConfig

val client = ThunderIDClient()

client.initialize(
    config = ThunderIDConfig(
        baseUrl = "https://localhost:8090",
        clientId = "<your-client-id>",
        scopes = listOf("openid", "profile", "email"),
        afterSignInUrl = "dev.thunderid.app://callback",
        afterSignOutUrl = "dev.thunderid.app://logout"
    )
)
```

:::note
When using `dev.thunderid:compose`, you do not need to create a `ThunderIDClient` directly. Wrap your UI in `ThunderIDProvider(config = ...)` and access the client through `LocalThunderID.current.client`.
:::

## Initialization

### `initialize(config, storage)`

Initializes the SDK. You must call this before calling any other method.

```kotlin
suspend fun initialize(config: ThunderIDConfig, storage: StorageAdapter? = null): Boolean
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `config` | `ThunderIDConfig` | ✅ | SDK configuration. See [Configuration](../configuration). |
| `storage` | `StorageAdapter?` | ❌ | Custom token storage backend. Defaults to `EncryptedStorageAdapter`. |

**Returns:** `true` when initialization succeeds.

**Throws:** `IAMException` with code `ALREADY_INITIALIZED` if the SDK is already initialized, or `INVALID_CONFIGURATION` if `baseUrl` is empty or does not use HTTPS.

### `reInitialize(baseUrl, clientId)`

Updates the base URL or client ID and reinitializes the SDK without creating a new instance.

```kotlin
suspend fun reInitialize(baseUrl: String? = null, clientId: String? = null): Boolean
```

**Throws:** `IAMException` with code `SDK_NOT_INITIALIZED` if `initialize()` has not been called first.

### `getConfiguration()`

Returns the current SDK configuration.

```kotlin
fun getConfiguration(): ThunderIDConfig
```

**Throws:** `IAMException` with code `SDK_NOT_INITIALIZED` if the SDK has not been initialized.

## App-Native Authentication

These methods drive the Flow Execution API loop for embedded (in-app) sign-in without leaving your application.

### `signIn(payload, request)`

Submits a step in the sign-in flow. Call this in a loop: first with an empty payload to initiate the flow, then with user inputs and the action ID to advance each step until `flowStatus` is `COMPLETE`.

```kotlin
suspend fun signIn(
    payload: EmbeddedSignInPayload,
    request: EmbeddedFlowRequestConfig
): EmbeddedFlowResponse
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `payload` | `EmbeddedSignInPayload` | ✅ | Flow step payload. Set `flowId` to `null` on the first call to initiate. |
| `request` | `EmbeddedFlowRequestConfig` | ✅ | Flow configuration including the application ID and flow type. |

**Returns:** `EmbeddedFlowResponse` with `flowStatus` of `PROMPT_ONLY` (more steps needed), `COMPLETE` (tokens issued), or `ERROR`.

:::note
The `SignIn` and `SignUp` composables manage this loop for you. Use `signIn(payload, request)` directly only when building a fully custom sign-in UI.
:::

### `signUp(payload, request)`

Submits a step in the registration flow. Same loop pattern as `signIn`.

```kotlin
suspend fun signUp(
    payload: EmbeddedSignInPayload? = null,
    request: EmbeddedFlowRequestConfig? = null
): EmbeddedFlowResponse
```

## Redirect-Based Authentication

These methods implement the OAuth 2.0 Authorization Code flow with PKCE for apps that redirect to a browser.

### `buildSignInUrl(options)`

Builds the OAuth 2.0 authorization URL to open in a `CustomTabsIntent` or browser.

```kotlin
fun buildSignInUrl(options: SignInOptions? = null): String
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `options` | `SignInOptions?` | ❌ | Optional sign-in hints: `prompt`, `loginHint`, `fidp`. `organizationUnitId` bounds the sign-in to that organization unit: the URL goes to `{baseUrl}/ou/{organizationUnitId}/oauth2/authorize`, and `handleRedirectCallback` redeems the code at that organization unit's token endpoint. |

**Returns:** The authorization URL string with PKCE `code_challenge` and `code_challenge_method=S256` parameters.

**Throws:** `IAMException` with code `INVALID_CONFIGURATION` if `clientId` is not set.

### `handleRedirectCallback(url)`

Exchanges the authorization code from the callback URL for tokens and returns the signed-in user.

```kotlin
suspend fun handleRedirectCallback(url: String): User
```

**Throws:** `IAMException` with code `INVALID_GRANT` if the URL does not contain a valid authorization code, or if the PKCE verifier is missing (call `buildSignInUrl` first).

## Session

### `isSignedIn()`

Returns `true` if an access token is present in the token store.

```kotlin
suspend fun isSignedIn(): Boolean
```

### `signOut(options)`

Revokes the refresh token, clears the local session, and returns the post-logout redirect URL.

```kotlin
suspend fun signOut(options: SignOutOptions? = null): String
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `options` | `SignOutOptions?` | ❌ | Optional: `idTokenHint` for server-side logout. |

**Returns:** The `afterSignOutUrl` from your configuration, or `"/"` if not set.

### `clearSession()`

Clears the local session without revoking the refresh token on the server.

```kotlin
fun clearSession()
```

### `isLoading()`

Returns `true` while a sign-in or sign-out operation is in progress.

```kotlin
fun isLoading(): Boolean
```

## Token Management

### `getAccessToken()`

Returns the current access token, automatically refreshing it if expired.

```kotlin
suspend fun getAccessToken(): String
```

**Throws:** `IAMException` with code `SESSION_EXPIRED` if the refresh token is also expired.

### `decodeJwtToken(token)`

Decodes a JWT string into a `Map<String, Any?>`.

```kotlin
fun decodeJwtToken(token: String): Map<String, Any?>
```

**Throws:** `IAMException` with code `INVALID_INPUT` if the token is not a valid JWT.

Example: decode access token claims:

```kotlin
val token = client.getAccessToken()
val claims = client.decodeJwtToken(token)
val sub = claims["sub"] as? String
```

### `exchangeToken(config)`

Performs an OAuth 2.0 token exchange (RFC 8693). Useful for Security Token Service (STS) scenarios.

```kotlin
suspend fun exchangeToken(config: TokenExchangeRequestConfig): TokenResponse
```

## User and Profile

### `getUser()`

Returns the authenticated user. Reads claims from the access token JWT if available; otherwise calls `/oauth2/userinfo`.

```kotlin
suspend fun getUser(): User
```

**Returns:** A `User` with `sub`, `username`, `email`, `displayName`, `profilePicture`, and raw `claims`.

### `getUserProfile()`

Fetches the full user profile from `/scim2/Me`.

```kotlin
suspend fun getUserProfile(): UserProfile
```

### `updateUserProfile(payload, userId)`

Updates the user profile via `/scim2/Me` (or `/scim2/Users/<userId>` if `userId` is provided).

```kotlin
suspend fun updateUserProfile(payload: Map<String, Any>, userId: String? = null): User
```

## Organization Units

These methods list the organization units the signed-in user can access and switch the session between them. To learn how a switch reuses the single sign-on (SSO) session and what changes in the new tokens, see [Switch Organizations](../../../../use-cases/b2b/journeys/switch-organizations). To show the list and the switch as a dropdown, use the [`OrganizationUnitSwitcher`](../components/organization-unit-switcher) composable.

### `getAccessibleOrganizationUnits(options)`

Lists the organization units the signed-in user can access: the one the user lives in and every one the user is shared into. It calls `GET /users/me/ous` with the user's access token.

```kotlin
suspend fun getAccessibleOrganizationUnits(
    options: AccessibleOrganizationUnitsOptions = AccessibleOrganizationUnitsOptions()
): AccessibleOrganizationUnits
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `options` | `AccessibleOrganizationUnitsOptions` | ❌ | Narrows and pages the list. |

`AccessibleOrganizationUnitsOptions` parameters:

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `scope` | `OrganizationUnitScope?` | `null` | `OrganizationUnitScope.SIBLINGS` lists the accessible organization units that share the parent of the current organization unit, without the parent itself. `null` lists every accessible organization unit. |
| `limit` | `Int?` | `null` | Page size. `null` uses the server's default. |
| `offset` | `Int?` | `null` | The 0-based index of the page's first organization unit. |

**Returns:** `AccessibleOrganizationUnits`:

| Property | Type | Description |
| :--- | :--- | :--- |
| `current` | `String?` | ID of the organization unit the list is relative to: the one the access token was issued for, or the user's own when the token names none. It is returned for every scope and page, so `organizationUnits` might not contain it. |
| `organizationUnits` | `List<AccessibleOrganizationUnit>` | The page of organization units. Each has an `id`, and a nullable `handle` and `name`. |
| `totalResults` | `Int` | Number of accessible organization units across all pages. |
| `startIndex` | `Int` | The start index the server reports for this page. |
| `count` | `Int` | Number of organization units on this page. |

Example: list the organization units that share the current one's parent:

```kotlin
import dev.thunderid.android.api.account.AccessibleOrganizationUnitsOptions
import dev.thunderid.android.api.account.OrganizationUnitScope

val page = client.getAccessibleOrganizationUnits(
    AccessibleOrganizationUnitsOptions(scope = OrganizationUnitScope.SIBLINGS, limit = 20)
)
page.organizationUnits.forEach { unit ->
    println("${unit.name ?: unit.handle ?: unit.id} (${unit.id})")
}
```

### `getCurrentOrganizationUnit()`

Returns the organization unit the session was issued for, read from its `ouId`, `ouHandle`, and `ouName` claims.

```kotlin
suspend fun getCurrentOrganizationUnit(): CurrentOrganizationUnit?
```

**Returns:** A `CurrentOrganizationUnit` with `id`, `handle`, and `name`, or `null` when no user is signed in or the session names no organization unit. The SDK reads the claims from the ID token, then from the access token. When sign-in runs on a backend, it reads them from the session the backend reports.

:::note
Use the result for display only, never for an authorization decision. The server decides every request from the access token.
:::

### `switchOrganizationUnit(ouId, options)`

Signs in again, bounded to the organization unit `ouId`. The server reuses the SSO session when the user can sign in to that organization unit, so the user normally enters no credentials.

```kotlin
suspend fun switchOrganizationUnit(
    ouId: String,
    options: SwitchOrganizationUnitOptions = SwitchOrganizationUnitOptions()
): OrganizationUnitSwitchResult
```

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `ouId` | `String` | ✅ | ID of the organization unit to switch to, such as an `id` from `getAccessibleOrganizationUnits`. |
| `options` | `SwitchOrganizationUnitOptions` | ❌ | How the switch runs. |

`SwitchOrganizationUnitOptions` parameters:

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `browser` | `(suspend (url: String) -> String)?` | `null` | Opens a sign-in URL and returns the URL the browser came back to. `customTabBrowser(context)` returns one that opens a Custom Tab. The host Activity forwards the redirect to `FederatedAuthSession.onRedirect`, as for [federated sign-in](../components/sign-in#setting-up-federated-sign-in). |
| `applicationId` | `String?` | `null` | The application whose `AUTHENTICATION` flow an app-native switch runs. `null` uses `applicationId` from the configuration. |
| `signInOptions` | `SignInOptions` | `SignInOptions()` | Extra authorization request parameters for a browser switch, such as `prompt`. The SDK replaces its `organizationUnitId` with `ouId`. |

The switch takes the first path that applies:

1. **Backend.** When sign-in runs on a backend (`endpoints.backend` is set), the SDK sends `POST {ouSwitch}?ouId=<id>` with `{"ouId": "<id>"}` as a JSON body, then reads the session again. No browser opens. `ouSwitch` is a path under `baseUrl` or an HTTPS URL, and defaults to `/api/auth/switch`. A refusal with `interaction_required`, `login_required`, `consent_required`, or `account_selection_required`, or a `401`, means the user has to sign in. If you pass `browser`, the SDK then opens the backend's sign-in for the organization unit through it. No other path runs in backend mode.
2. **Device secret.** When the session holds a device secret, issued to a sign-in that requested the `device_sso` scope, and the configuration sets `clientId`, the SDK exchanges the secret at `{baseUrl}/ou/{ouId}/oauth2/token`. No browser opens. The SDK deletes a secret that the server refuses with `invalid_request` or `invalid_grant`. Any refusal other than an unavailable organization unit moves on to the next path.
3. **Browser.** When you pass `browser`, the SDK opens a redirect sign-in bounded to the organization unit and redeems the code at `{baseUrl}/ou/{ouId}/oauth2/token`.
4. **App-native flow.** Otherwise, the SDK starts the application's `AUTHENTICATION` flow with `ouId`. It presents the SSO session handles kept from earlier flow steps, so the server can reuse the SSO session without a browser cookie. It returns `SignInRequired` when the flow needs the user.

On success, the SDK replaces the whole token set, so the refresh token is bound to the new organization unit. It keeps the device secret and the SSO session handles, and reads the user again. When you call this method directly in a Compose app, call `ThunderIDState.refresh()` afterward so composables read the new user. `OrganizationUnitSwitcher` does this for you.

If the switch fails, the previous session stays as it was. In backend mode, a `401` or a `login_required` refusal means the backend holds no session to switch, so the SDK also signs the user out locally.

**Returns:** `OrganizationUnitSwitchResult`, one of:

| Result | Description |
| :--- | :--- |
| `OrganizationUnitSwitchResult.Switched(user)` | The client holds the new organization unit's session. `user` is the user read again. |
| `OrganizationUnitSwitchResult.SignInRequired(response)` | The app-native flow needs the user, for example for credentials the SSO session could not supply. Drive `response` with `signIn(payload, request)`, passing its `flowId`, like any app-native flow. The previous session stays until the flow completes. |

**Throws:** `IAMException`. The codes specific to a switch:

| Code | When |
| :--- | :--- |
| `ORGANIZATION_UNIT_UNAVAILABLE` | The organization unit does not exist, or the application cannot be used from it. The server does not tell the two apart. |
| `INVALID_INPUT` | `ouId` is blank. |
| `INVALID_CONFIGURATION` | No path applies: no backend, no usable device secret, no `browser`, and no `applicationId`. When a device secret exchange failed first, that failure is thrown instead. |
| `AUTHENTICATION_FAILED` | The backend, the bounded browser sign-in, or the app-native flow refused the switch for another reason. |

Example: switch, with a Custom Tab as the fallback when neither a backend nor a device secret can switch:

```kotlin
import dev.thunderid.android.IAMException
import dev.thunderid.android.ThunderIDErrorCode
import dev.thunderid.android.api.auth.OrganizationUnitSwitchResult
import dev.thunderid.android.api.auth.SwitchOrganizationUnitOptions
import dev.thunderid.android.api.auth.customTabBrowser

try {
    val result = client.switchOrganizationUnit(
        ouId = organizationUnitId,
        options = SwitchOrganizationUnitOptions(browser = customTabBrowser(context))
    )
    if (result is OrganizationUnitSwitchResult.Switched) {
        println("Switched to ${client.getCurrentOrganizationUnit()?.name}")
    }
} catch (e: IAMException) {
    if (e.code == ThunderIDErrorCode.ORGANIZATION_UNIT_UNAVAILABLE) {
        println("This organization unit is not available to this application.")
    }
}
```

## Error Handling

All suspending methods throw `IAMException` on failure. Catch it to handle errors:

```kotlin
try {
    val user = client.getUser()
} catch (e: IAMException) {
    println("[${e.code}] ${e.message}")
} catch (e: Exception) {
    println("Unexpected error: $e")
}
```

### Error Codes

| Code | Description |
| :--- | :--- |
| `SDK_NOT_INITIALIZED` | A method was called before `initialize()` |
| `ALREADY_INITIALIZED` | `initialize()` was called more than once |
| `INVALID_CONFIGURATION` | Missing or invalid configuration value |
| `INVALID_REDIRECT_URI` | The redirect URI is not registered |
| `AUTHENTICATION_FAILED` | Credentials are incorrect |
| `USER_ACCOUNT_LOCKED` | The user account is locked |
| `USER_ACCOUNT_DISABLED` | The user account is disabled |
| `SESSION_EXPIRED` | The session has expired and cannot be refreshed |
| `MFA_REQUIRED` | Multi-factor authentication is required |
| `MFA_FAILED` | Multi-factor authentication failed |
| `INVALID_GRANT` | The authorization code or token is invalid |
| `CONSENT_REQUIRED` | User consent is required |
| `ORGANIZATION_UNIT_UNAVAILABLE` | The organization unit does not exist, or the application cannot be used from it |
| `USER_ALREADY_EXISTS` | Registration failed because the user already exists |
| `INVALID_INPUT` | Input validation failed |
| `INVITATION_CODE_INVALID` | The invitation code is not valid |
| `INVITATION_CODE_EXPIRED` | The invitation code has expired |
| `REGISTRATION_DISABLED` | Registration is disabled for this application |
| `RECOVERY_FAILED` | Password recovery failed |
| `CONFIRMATION_CODE_INVALID` | The confirmation code is not valid |
| `CONFIRMATION_CODE_EXPIRED` | The confirmation code has expired |
| `FORBIDDEN` | The server returned HTTP 403 |
| `NOT_FOUND` | The server returned HTTP 404 |
| `NETWORK_ERROR` | A network request failed |
| `REQUEST_TIMEOUT` | The request timed out |
| `SERVER_ERROR` | The server returned an error response |
| `UNKNOWN_ERROR` | An unexpected error occurred |

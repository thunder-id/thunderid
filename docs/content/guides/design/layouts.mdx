# Layouts

A layout defines the structural composition of authentication screens. While a [theme](../themes) controls visual styling (colors, fonts), a layout controls how screen elements are arranged, including header, main content area, and footer slots, along with their sizing, spacing, and visibility.

## Layout Properties

Each layout includes the following configurable properties. For detailed property references, see [Design Catalog](../design-catalog#layout-properties).

| Property | Description |
|----------|-------------|
| **Screen Type** | The `centered` template, which positions the main content container at the center of the screen. See [Screen Type](../design-catalog#screen-type). |
| **Custom Stylesheets** | Inject inline or external CSS stylesheets for customizations beyond theme properties. See [Custom Stylesheets](../design-catalog#custom-stylesheets). |

## Create a Layout

<Stepper stepNode="h3" as="h3">

### Create the Layout

The Console does not create layouts. Send a `POST` request to `/design/layouts` with the layout's handle, display name, and configuration. On the control plane, also set `projectId` to the project the layout belongs to. The server returns `201` with the created layout.

**Request:**
```bash
curl -X POST https://localhost:8090/design/layouts \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "handle": "my-layout",
    "displayName": "My Layout",
    "projectId": "<project-id>",
    "layout": {}
  }'
```

### Customize the Layout

1. Sign in to the <ProductName /> Console. On the control plane, open the project the layout belongs to.
2. Navigate to **Design** from the sidebar. On the control plane, it is under **Customize** in the project.
3. In the **Layouts** section, click the layout. The layout builder opens.

Use the layout builder to adjust your layout:

- **Theme Preview**: Preview how the layout pairs with different themes.
- **Custom CSS**: Add inline or external stylesheets from the right panel.
- **Element inspector**: Click any element in the preview to auto-generate a CSS selector.

Click **Save** to apply your changes.

### Assign the Layout to an Application

Open your application in the <ProductName /> Console, navigate to **Customization** settings, and select your layout.

</Stepper>

## Update a Layout

1. Navigate to **Design** in the <ProductName /> Console and click the layout you want to edit. On the control plane, open the layout's project first and select **Design** under **Customize**. The layout builder opens with a live preview.
2. Edit your custom stylesheets in the right panel, or use the element inspector to target specific elements.
3. Click **Save** to apply your changes.

Changes take effect immediately for new authentication sessions.

## Delete a Layout

You cannot delete layouts created through the Console from the Console. Use the API to delete a layout.

Send a `DELETE` request to `/design/layouts/{id}`. The server returns `204` on success.

**Request:**
```bash
curl -X DELETE https://localhost:8090/design/layouts/{id} \
  -H "Authorization: Bearer <access_token>"
```

:::warning
You cannot delete a layout that is currently assigned to an application. Remove the layout from all applications before deleting it.
:::

## Layouts in Projects

On the control plane, every layout belongs to a project. Create a layout with the `projectId` of its project in the request body of `POST /design/layouts`. A request without `projectId` fails with `LAY-1020`, and a project that does not exist fails it with `LAY-1019`. To learn what a project is, see [Projects](../../key-concepts/projects.mdx).

- **List**: `GET /design/layouts?projectId=<project-id>` returns the layouts of the project. A project that does not exist returns an empty list.
- **Update**: an update without `projectId` keeps the layout in its current project. A different `projectId` moves the layout to that project.
- **Delete a project**: a project that still has layouts cannot be deleted. The request fails with `409` (`PRJ-1013`) until its layouts are deleted or moved to another project.

In the control plane Console, open a project and select **Design** under **Customize** to see the layouts of that project.

The built-in **Centered** layout belongs to the **Default** project. A server without projects, such as the all-in-one server, does not require a project and keeps the `projectId` it receives without checking it, but refuses one longer than 36 characters with `LAY-1019`.

On the control plane, a declarative layout file must set `projectId`. A file without it stops the server from starting. Export and import keep `projectId`.

# Template Resources

A notification template is a declarative resource. <ProductName /> stores templates in its database and manages them at runtime, and `resource_type: notification_template` is how you create or update one from a configuration file rather than the Console or API.

A template is keyed by its channel and handle. The handle is unique within a channel and does not change after creation, so importing a document with the same `(channel, handle)` and `upsert` enabled updates the existing template, while a new handle creates one.

```yaml
resource_type: notification_template
channel: email
handle: user-invite
ouHandle: default
displayName: User Invitation Email
content:
  subject: "{{t(userInvite.email.subject)}}"
  body: "<p>{{t(userInvite.email.body)}}</p><p>{{ctx(inviteLink)}}</p>"
design:
  colorScheme: light
```

An `email` template carries a `subject` and may set a `design`; an `sms` template carries a `body` only, and a subject or design on it is rejected. For the full field reference and an SMS example, see the [`notification_template` resource](./import-resources#notification-templates).

Whether a declared template can also be edited through the API and Console depends on `notification.template.store`. With `mutable`, the default, declared templates are imported into the database and stay editable. With `declarative`, templates come from files alone and writes through the API are refused. With `composite`, file-declared templates are read-only alongside editable database templates.

This resource replaces the earlier file-based template store, which loaded templates keyed by `scenario` and `type` from a `templates` directory at startup. A template is now addressed by `(channel, handle)`, and the `scenario` and `type` fields no longer apply.

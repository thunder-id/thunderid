# `CookieConfig`

The Express SDK exports `CookieConfig` with the default values of the session cookie.

## Import

```js
const {CookieConfig} = require('@thunderid/express');
```

## Session Cookie Name

The session cookie name depends on the environment and the configuration:

| Condition | Name |
| :--- | :--- |
| `sessionCookie.name` is set | That name, as it is |
| The cookie is `Secure`, which is the default when `NODE_ENV` is `production` | `__Host-thunderid-session` |
| The cookie is not `Secure` | `thunderid-session` |

A custom `vendor` replaces `thunderid` in the default name. Read the name the SDK uses from `req.thunderIDAuth.getSessionCookieName()`.

## Default Cookie Values

| Property | Value |
| :--- | :--- |
| `defaultExpirySeconds` | `86400` |
| `defaultHttpOnly` | `true` |
| `defaultSameSite` | `'strict'` |
| `defaultSecure` | `false`. Deprecated and no longer read: the cookie is `Secure` by default when `NODE_ENV` is `production` |

## Usage

You do not need to set these values directly when `sessionCookie` options are omitted from `ExpressClientConfig`. The SDK uses these defaults automatically.

```js title="index.js" showLineNumbers
// Reports whether the request is signed in. The cookie's value is a credential, so it is never returned.
app.get('/signed-in', async (req, res) => {
  const sessionId = req.cookies?.[req.thunderIDAuth.getSessionCookieName()];

  res.json({isSignedIn: Boolean(sessionId && (await req.thunderIDAuth.isSignedIn(sessionId)))});
});
```

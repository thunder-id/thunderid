# `ThunderIDJavaScriptClient`

`ThunderIDJavaScriptClient` is the base class that all platform-specific <ProductName /> clients extend. It provides OIDC discovery, PKCE, token exchange, session management, JWT decoding, and agent/OBO authentication. Instantiate it directly only when writing a custom platform adapter: for browser use, prefer `@thunderid/browser`; for React, use `@thunderid/react`.

## Constructor

```ts
const client = new ThunderIDJavaScriptClient(storage?, cryptoUtils?)
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `storage` | `Storage` | `DefaultCacheStore` | Custom storage implementation for session and config data |
| `cryptoUtils` | `Crypto` | `DefaultCrypto` | Custom cryptographic utilities (PKCE, JWT decoding) |

## Methods

### Initialization

#### `initialize(config, storage?)`

Initialize the client with your application configuration. Must be called before using any other method.

```ts
await client.initialize({
  clientId: '<your-client-id>',
  baseUrl: 'https://localhost:8090',
  afterSignInUrl: 'http://localhost:3000',
  afterSignOutUrl: 'http://localhost:3000',
})
```

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `config` | `AuthClientConfig` | Application configuration. See [Configuration Reference](../configuration) |
| `storage` | `Storage` | Optional storage override for this instance |

**Returns:** `Promise<boolean>`, `true` when initialization completes.

#### `reInitialize(config)`

Update configuration at runtime without creating a new instance. Forces OIDC discovery to re-run.

```ts
await client.reInitialize({ scopes: ['openid', 'profile', 'email'] })
```

**Returns:** `Promise<boolean>`

#### `getConfiguration()`

Retrieve the current configuration stored for this instance.

```ts
const config = client.getConfiguration()
```

**Returns:** `T` (the configuration type)

### Authentication State

#### `isSignedIn(userId?)`

Check whether a user session is currently active (token exists and has not expired).

```ts
const signedIn = await client.isSignedIn()
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `string` | Optional session ID for multi-user scenarios |

**Returns:** `Promise<boolean>`

### Token Management

#### `getAccessToken(sessionId?)`

Retrieve the raw access token string for the current session.

```ts
const token = await client.getAccessToken()
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `sessionId` | `string` | Optional session ID for multi-user scenarios |

**Returns:** `Promise<string>`

#### `decodeJwtToken<R>(token)`

Decode a JWT token and return its payload as a typed object. Does not validate the signature.

```ts
const claims = await client.decodeJwtToken<{ sub: string; email: string }>(token)
console.log(claims.sub)
```

**Returns:** `Promise<R>`

#### `exchangeToken(config, sessionId?)`

Perform a token exchange request (RFC 8693 / custom grant). Sends a POST to the token endpoint with the provided data, optionally attaching the current access token.

```ts
const result = await client.exchangeToken({
  tokenEndpoint: 'https://localhost:8090/oauth2/token',
  data: {
    grant_type: 'urn:ietf:params:oauth:grant-type:token-exchange',
    subject_token: '{{token}}',
    subject_token_type: 'urn:ietf:params:oauth:token-type:access_token',
    resource: 'https://api.example.com/app',
  },
  attachToken: true,
  returnsSession: true,
})
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `config` | `TokenExchangeRequestConfig` | Token exchange configuration |
| `config.tokenEndpoint` | `string` | Token endpoint URL. Falls back to OIDC discovery |
| `config.data` | `Record<string, string>` | POST body fields. Use `{{token}}` to substitute the current access token |
| `config.attachToken` | `boolean` | Whether to include `Authorization: Bearer <token>` |
| `config.returnsSession` | `boolean` | When `true`, the response is stored as the new session |
| `sessionId` | `string` | Optional session ID |

**Returns:** `Promise<TokenResponse | Response | User>`

#### `getDiscoveryResponse()`

Retrieve the cached OIDC discovery document, or `null` if the client has not been initialized.

```ts
const discovery = await client.getDiscoveryResponse()
console.log(discovery?.token_endpoint)
```

**Returns:** `Promise<OIDCDiscoveryApiResponse | null>`

### User and Session

#### `getUser(userId?)`

Retrieve the authenticated user's identity claims, extracted from the stored ID token.

```ts
const user = await client.getUser()
console.log(user.displayName, user.email)
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `string` | Optional session ID |

**Returns:** `Promise<User>`

The `User` object includes:

| Property | Type | Description |
|----------|------|-------------|
| `displayName` | `string` | User's display name |
| `username` | `string` | Username |
| `email` | `string` | Email address |
| `given_name` | `string` | First name |
| `family_name` | `string` | Last name |
| `picture` | `string` | Profile picture URL |
| `sub` | `string` | Subject identifier |

#### `clearSession(sessionId?)`

Clear stored session data for a given session ID.

```ts
client.clearSession()
```

**Returns:** `void`

#### `setSession(sessionData, sessionId?)`

Manually write session data into storage. Use when handling the token response externally.

```ts
await client.setSession({ access_token: '...', id_token: '...', expires_in: '3600' })
```

**Returns:** `Promise<void>`

#### `getInstanceId()`

Return the numeric instance ID assigned to this client. Used to namespace storage when running multiple SDK instances.

```ts
const id = client.getInstanceId() // 0 by default
```

**Returns:** `number`

### Organization Units

The core defines how a client reads and changes the organization unit a session belongs to. For how a switch works across <ProductName /> and the SDKs, see [Switch Organizations](../../../../use-cases/b2b/journeys/switch-organizations).

#### `getCurrentOrganizationUnit(userId?)`

Read the organization unit the session was issued for from the `ouId`, `ouHandle`, and `ouName` claims of its ID token. The claims are not verified, so use the result for display only, never for an authorization decision.

```ts
const unit = await client.getCurrentOrganizationUnit()
console.log(unit?.id, unit?.name)
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `string` | Optional session ID for multi-user scenarios |

**Returns:** `Promise<CurrentOrganizationUnit | null>`, an object with `id` and, when the claims carry them, `handle` and `name`. `null` when the session is signed out or its ID token has no `ouId` claim.

#### `switchOrganizationUnit(organizationUnitId, options?)`

Sign in again, bounded to the organization unit `organizationUnitId`. On success a platform client replaces its tokens. On failure the previous session stays as it was, unless a backend reports that its session has ended, and the error carries a code from [`OrganizationUnitSwitchErrorCodes`](../errors#organizationunitswitcherrorcodes).

Each platform client implements the switch: see [`ThunderIDBrowserClient`](../../../browser/apis/thunderid-browser-client#switchorganizationunitorganizationunitid-options) and [`ThunderIDNodeClient`](../../../node/apis/clients/thunderid-node-client#switchorganizationunitorganizationunitid-options). The base class has no way to reach the user, so calling it on `ThunderIDJavaScriptClient` rejects with `ThunderIDRuntimeError` code `JS-AUTH_CORE-SWOU-NS01`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `organizationUnitId` | `string` | ID of the organization unit to switch to |
| `options.redirect` | `boolean` | Browser clients only. When <ProductName /> needs the user, fall back to a full-page redirect, or in backend mode to the backend's sign-in endpoint with `ouId`. Defaults to `true`. Set it to `false` to fail with `InteractionRequired` instead |
| `options[param]` | `unknown` | Any other key is an extra authorization request parameter for a redirect-mode sign-in. Backend and app-native switches ignore it |

**Returns:** `Promise<User | TokenResponse | undefined>`

#### `getAccessibleOrganizationUnits(config)`

Exported function that lists the organization units the signed-in user can access, from `GET {baseUrl}/users/me/ous`: the one the user lives in and every one the user is shared into. The request must carry the user's access token, so pass it in `headers` or pass a `fetcher` that attaches it. The function takes the same [request configuration](../management#request-configuration) as the management functions.

```ts
import { getAccessibleOrganizationUnits } from '@thunderid/javascript'

const { current, organizationUnits } = await getAccessibleOrganizationUnits({
  baseUrl: 'https://localhost:8090',
  headers: { Authorization: `Bearer ${await client.getAccessToken()}` },
  scope: 'siblings',
})
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `config.scope` | `'siblings'` | Keep only the accessible units that share the parent of the current unit. Omit it to list every accessible unit |
| `config.limit` | `number` | Maximum number of units to return |
| `config.offset` | `number` | Zero-based offset of the first unit to return |
| `config.url` | `string` | Absolute URL of the endpoint. Takes precedence over `baseUrl` |

**Returns:** `Promise<AccessibleOrganizationUnitList>`

| Property | Type | Description |
|----------|------|-------------|
| `current` | `string` | ID of the unit the list is relative to: the one the access token was issued for, or the user's own when the token names none. Returned whatever the scope or page |
| `organizationUnits` | `AccessibleOrganizationUnit[]` | The units in this page, each with `id`, `handle`, `name`, and an optional `logoUrl` |
| `totalResults` | `number` | Number of units the listing matches |
| `startIndex` | `number` | One-based index of the first unit in this page |
| `count` | `number` | Number of units in this page |

The function throws [`ThunderIDAPIError`](../errors#thunderidapierror) with the same codes as the [management functions](../management#error-handling), prefixed with `getAccessibleOrganizationUnits`.

### Agent and OBO Authentication

#### `getAgentToken(agentConfig)`

Authenticate as a service agent using the embedded sign-in flow and return a token.

```ts
const token = await client.getAgentToken({
  agentID: 'my-agent@org.com',
  agentSecret: 'secret',
})
```

**Returns:** `Promise<TokenResponse>`

#### `getOBOSignInURL(agentConfig)`

Build an On-Behalf-Of (OBO) authorization URL that includes the agent's `requested_actor` parameter.

```ts
const url = await client.getOBOSignInURL({ agentID: 'my-agent@org.com', agentSecret: 'secret' })

```

**Returns:** `Promise<string>`

#### `getOBOToken(agentConfig, authCodeResponse)`

Exchange an authorization code plus an agent token for an OBO access token.

```ts
const token = await client.getOBOToken(agentConfig, {
  code: params.get('code')!,
  state: params.get('state')!,
})
```

**Returns:** `Promise<TokenResponse>`


**Returns:** `boolean`

### Backchannel Authentication (CIBA)

These methods implement the OpenID Connect Client-Initiated Backchannel Authentication (CIBA) poll-mode flow. Use them to trigger user authentication on a separate device without a browser redirect. Push mode is **not** supported. For protocol details, see the [Backchannel Authentication guide](../../../../guides/protocols/oauth-oidc/backchannel-authentication).

#### `initiateCIBA(options)`

Send a backchannel authentication request to `POST /oauth2/bc-authorize` and return the `auth_req_id` needed to begin polling.

The endpoint URL is discovered automatically from the OIDC discovery document. Scopes are sourced from the `scopes` field you supplied to `initialize()`.

```ts
const { authReqId, interval, expiresIn } = await client.initiateCIBA({
  loginHint: 'user@example.com',
  bindingMessage: 'Approve login from call center',
})
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `options.loginHint` | `string` | One of two | A hint identifying the end-user, typically an email address, phone number, or username. |
| `options.idTokenHint` | `string` | One of two | A previously issued ID token that identifies the end-user. |
| `options.loginHintToken` | `string` | No | Defined in the CIBA specification but **not supported** by <ProductName />. The server returns `invalid_request` when this parameter is provided. |
| `options.bindingMessage` | `string` | No | A short, human-readable string displayed on both the consumption and authentication devices to bind the two interactions. Maximum 256 printable characters. |
| `options.requestedExpiry` | `number` | No | Requested lifetime in seconds for the `auth_req_id`. The server clamps values above its maximum. |
| `options.acrValues` | `string` | No | Space-separated Authentication Context Class Reference values. |
| `options.authorizationDetails` | `AuthorizationDetail[]` | No | RFC 9396 authorization details to request, sent JSON-encoded as the `authorization_details` parameter. Takes precedence over the `authorizationDetails` configuration. See [Rich Authorization Requests](#rich-authorization-requests). |

Exactly one of `loginHint` or `idTokenHint` must be provided.

**Returns:** `Promise<CIBAInitiateResponse>`

| Field | Type | Description |
|-------|------|-------------|
| `authReqId` | `string` | Unique identifier for this authentication request. Pass to `pollCIBA()`. |
| `interval` | `number` | Minimum seconds between polling attempts. Increase by 5 on `slow_down`. |
| `expiresIn` | `number` | Lifetime in seconds of the `auth_req_id`. |

**Throws:** `ThunderIDAPIError` with code `JS-AUTH_CORE-CIBA1-HE03` when the server rejects the request.

#### `pollCIBA(authReqId, interval, options?)`

Poll `POST /oauth2/token` with `grant_type=urn:openid:params:grant-type:ciba` until the user authenticates, the request expires, or polling is cancelled. On success, the received tokens are stored in the SDK session.

```ts
const controller = new AbortController()

// Cancel polling after 2 minutes if the user has not yet responded.
setTimeout(() => controller.abort(), 120_000)

try {
  const tokens = await client.pollCIBA(authReqId, interval, {
    signal: controller.signal,
  })
} catch (err) {
  if (err.code === 'JS-AUTH_CORE-CIBA2-AB05') {
    console.log('Polling cancelled — user did not respond in time.')
  }
}
```

`signal` accepts a standard [`AbortSignal`](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal). Call `controller.abort()` at any time to stop polling immediately, even when the method is sleeping between attempts.

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `authReqId` | `string` | Yes | The `authReqId` returned by `initiateCIBA()`. |
| `interval` | `number` | Yes | Initial polling interval in seconds, as returned by `initiateCIBA()`. |
| `options.signal` | `AbortSignal` | No | Cancels polling immediately, interrupting any in-progress sleep. |

**Polling behavior:**

| Server response | Action |
|---|---|
| `authorization_pending` | Wait for the current interval, then retry. |
| `slow_down` | Permanently increase the interval by 5 seconds, wait, then retry. |
| `expired_token` | Reject immediately. |
| `access_denied` | Reject immediately. |
| Successful token response | Store tokens in the SDK session and resolve. |

**Returns:** `Promise<TokenResponse>`

**Throws:**

| Code | Cause |
|------|-------|
| `JS-AUTH_CORE-CIBA2-HE03` | The server returned a terminal error (`expired_token`, `access_denied`, or another non-retryable error). |
| `JS-AUTH_CORE-CIBA2-AB05` | Polling was cancelled via `AbortSignal`. |

### Rich Authorization Requests

The client requests [RFC 9396](https://datatracker.ietf.org/doc/html/rfc9396) authorization details from the [`authorizationDetails`](../configuration#authorization-details) configuration and from the `authorizationDetails` option of a single request. For the protocol and the server setup, see [Rich Authorization Requests](../../../../guides/protocols/oauth-oidc/rich-authorization-requests).

#### Request Options

| Request | Option | Precedence |
|---------|--------|------------|
| Sign-in | `authorizationDetails` in the sign-in options of a platform client's `signIn()`, which reach `getSignInUrl(requestConfig)` | Replaces the configured `authorizationDetails` for this sign-in |
| Backchannel authentication | `authorizationDetails` in the [`initiateCIBA(options)`](#initiatecibaoptions) options | Replaces the configured `authorizationDetails` for this request |
| Client credentials token | None. `getAccessToken()` sends the configured `authorizationDetails` when `grantType` is `'client_credentials'` | Not applicable |

#### `AuthorizationDetail`

One authorization the client requests, or that the server reports as granted.

| Property | Type | Description |
|----------|------|-------------|
| `type` | `string` | Required. A type registered on the server, which defines every other member |
| `actions` | `string[]` | Kinds of actions to take at the resource |
| `datatypes` | `string[]` | Kinds of data requested from the resource |
| `identifier` | `string` | A specific resource available at the API |
| `locations` | `string[]` | Locations of the resources or resource servers the detail applies to |
| `privileges` | `string[]` | Privilege levels at the resource |
| `[member: string]` | `unknown` | Any other member the type defines, such as `instructedAmount` |

The server accepts only the members a type's schema declares, including the common members above.

#### Granted Authorization Details

The details the server grants can differ from the ones requested: the user may lower a value or decline a detail on the consent step, and a type's processor may fill in a field. Read what was granted from these places:

| Where | Field |
|-------|-------|
| `TokenResponse` from a server-side `signIn()`, such as the [Express SDK](../../../express/apis/configuration/express-client-config) `onSignIn` callback | `authorizationDetails?: AuthorizationDetail[]`, present only when the server returns `authorization_details` |
| Stored session (`SessionData`) | `authorization_details?: AuthorizationDetail[]` |
| `getUserSession()` (protected) | `authorizationDetails?: AuthorizationDetail[]` |
| The access token | The `authorization_details` claim |

#### `getSupportedAuthorizationDetailsTypes(config)`

Exported function that reads every authorization details type a client may request from the server's public types endpoint, `{baseUrl}/oauth2/authorization-details-types`. The endpoint needs no access token.

```ts
import { getSupportedAuthorizationDetailsTypes } from '@thunderid/javascript'

const { types } = await getSupportedAuthorizationDetailsTypes({ baseUrl: 'https://localhost:8090' })

for (const type of types) {
  console.log(type.type, type.modifications)
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `config.baseUrl` | `string` | Base URL of the <ProductName /> instance |
| `config.url` | `string` | Absolute URL of the types endpoint, such as the `authorization_details_types_endpoint` from the server's discovery document. Takes precedence over `baseUrl` |
| `config.fetcher` | `(url: string, config: RequestInit) => Promise<Response>` | Performs the request. Defaults to the global `fetch` |

**Returns:** `Promise<SupportedAuthorizationDetailsTypesResponse>`, an object with a `types` array of `SupportedAuthorizationDetailsType`.

#### `getSupportedAuthorizationDetailsType(config)`

Exported function that reads one type by its `type` value from `{baseUrl}/oauth2/authorization-details-types/{type}`. It takes the same options as `getSupportedAuthorizationDetailsTypes()`, plus `config.type`, which is percent-encoded as one path segment.

```ts
import { getSupportedAuthorizationDetailsType, ThunderIDAPIError } from '@thunderid/javascript'

try {
  const paymentType = await getSupportedAuthorizationDetailsType({
    baseUrl: 'https://localhost:8090',
    type: 'payment_initiation',
  })
  console.log(paymentType.version, paymentType.schema)
} catch (err) {
  if (err instanceof ThunderIDAPIError && err.code === 'getSupportedAuthorizationDetailsType-NotFoundError-001') {
    // The server has no type with this value.
  }
}
```

**Returns:** `Promise<SupportedAuthorizationDetailsType>`

`SupportedAuthorizationDetailsType` is the request view of a type. It leaves out the type's processor, consent summary, and reuse settings.

| Property | Type | Description |
|----------|------|-------------|
| `type` | `string` | The value a client sends as the `type` of a detail |
| `name` | `string` | Display name of the type |
| `description` | `string` | Description of the type, when it has one |
| `version` | `number` | Version of the type |
| `schema` | `Record<string, unknown>` | The type's JSON Schema as a client sees it: field policies are left out, and so are fields only the processor supplies |
| `modifications` | `SupportedAuthorizationDetailsTypeModification[]` | The changes a client may make to a granted detail at the token endpoint, each with `field` (the dot-separated path) and `modification` (`'decrease'`, `'increase'`, `'removeItems'`, or `'addItems'`). A field only the user may change on the consent step is not listed |

Both functions throw [`ThunderIDAPIError`](../errors#thunderidapierror) with the same codes as the [management functions](../management#error-handling), prefixed with the function name.

#### Errors

| Request | When the server rejects the authorization details |
|---------|------|
| Sign-in | The server redirects back to `afterSignInUrl` with `error=invalid_authorization_details` and an `error_description` in the query, and the user stays signed out. In the browser SDK, the next `signIn()` call throws `ThunderIDAuthException` with code `SPA-AUTH_HELPER-SI-SE01`, whose `name` is the error and `message` the description, and removes both from the URL. In the Express SDK, `handleSignIn()` passes `ThunderIDAuthException` with code `EXPRESS-CLIENT-SI-IV01` to `onError` |
| `initiateCIBA()` | Throws `ThunderIDAPIError` with code `JS-AUTH_CORE-CIBA1-HE03`. The message carries the server's `invalid_authorization_details` description |
| `getAccessToken()` with the `client_credentials` grant | Throws `ThunderIDAuthException` with code `JS-AUTH_CORE-RCCT-HE03`. The message carries the server's `invalid_authorization_details` description |

### Protected Methods (for subclass use)

These methods are available to subclasses building platform adapters:

| Method | Description |
|--------|-------------|
| `loadOpenIDProviderConfiguration(forceInit?)` | Fetch and cache the OIDC discovery document |
| `getSignInUrl(requestConfig?, userId?)` | Build the OAuth 2.0 authorization URL with PKCE. `requestConfig.authorizationDetails` overrides the configured authorization details for this request. `requestConfig.organizationUnitId` bounds the sign-in to that organization unit: the URL points at `/ou/{ouId}/oauth2/authorize`, and `requestAccessToken()` redeems the code at `/ou/{ouId}/oauth2/token` |
| `requestAccessToken(code, sessionState, state, userId?, tokenRequestConfig?)` | Exchange an authorization code for tokens |
| `isOrganizationUnitBoundRequest(state, userId?)` | Whether the authorization request that `state` belongs to was bounded to an organization unit, so its callback replaces a session that is still signed in |
| `switchOrganizationUnitWithDeviceSecret(organizationUnitId, sessionId?)` | Exchange the session's device secret at the unit's token endpoint, `/ou/{ouId}/oauth2/token`, with no redirect. On success the unit's tokens replace the session's. Returns the new tokens or the server's OAuth error, or `undefined` when the session holds no device secret |
| `getSignOutUrl(userId?)` | Build the OIDC end-session URL |
| `refreshAccessToken(userId?)` | Use the refresh token to get a new access token |
| `revokeAccessToken(userId?)` | Revoke the current access token |
| `getDecodedIdToken(userId?, idToken?)` | Decode the stored ID token |
| `getIdToken(userId?)` | Get the raw ID token string |
| `getUserSession(userId?)` | Get the granted scopes and authorization details for the current session |
| `getOpenIDProviderEndpoints()` | Get the cached OIDC endpoint URLs |
| `getStorageManager()` | Access the underlying `StorageManager` instance |
| `getCryptoHelper()` | Access the underlying `IsomorphicCrypto` instance |
